# Cashfree Payment Gateway Setup Guide

This guide will help you set up Cashfree payment gateway for your Mridang e-commerce application.

## 🔑 Get Cashfree Credentials

### Step 1: Create Cashfree Account

1. Go to [Cashfree Payments](https://www.cashfree.com/)
2. Click on "Sign Up" or "Get Started"
3. Complete the registration process with your business details
4. Verify your email address

### Step 2: Access Developer Credentials

1. Log in to your [Cashfree Dashboard](https://merchant.cashfree.com/merchants/login)
2. Navigate to **"Developers"** section from the left sidebar
3. You'll see two environments:
   - **Sandbox (Test Mode)** - For development and testing
   - **Production** - For live transactions

### Step 3: Get API Credentials

**For Testing (Sandbox):**
1. Click on **"Sandbox"** tab
2. Copy your:
   - **App ID** (Client ID)
   - **Secret Key**
3. Note: Sandbox credentials are automatically generated

**For Production:**
1. Complete KYC verification (required before going live)
2. Upload business documents (PAN, GST, Bank details, etc.)
3. Wait for approval (usually 24-48 hours)
4. Once approved, click on **"Production"** tab
5. Copy your:
   - **App ID** (Client ID)
   - **Secret Key**

## 🔧 Environment Variables Setup

Create a `.env.local` file in the root of your project (if it doesn't exist) and add the following environment variables:

### For Development/Testing (Sandbox):

```env
# Cashfree Payment Gateway - SANDBOX (Test Mode)
CASHFREE_APP_ID=your_sandbox_app_id_here
CASHFREE_SECRET_KEY=your_sandbox_secret_key_here
CASHFREE_ENVIRONMENT=sandbox

# Database Configuration
DB_HOST=localhost
DB_USER=your_database_user
DB_PASS=your_database_password
DB_NAME=your_database_name
DB_PORT=3306

# Email Configuration (for order confirmations)
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USER=your_email@gmail.com
EMAIL_PASS=your_email_password
EMAIL_FROM=your_email@gmail.com

# Application URL
NEXT_PUBLIC_APP_URL=http://localhost:3000
```

### For Production:

```env
# Cashfree Payment Gateway - PRODUCTION (Live Mode)
CASHFREE_APP_ID=your_production_app_id_here
CASHFREE_SECRET_KEY=your_production_secret_key_here
CASHFREE_ENVIRONMENT=production

# Database Configuration
DB_HOST=your_production_db_host
DB_USER=your_production_db_user
DB_PASS=your_production_db_password
DB_NAME=your_production_db_name
DB_PORT=3306

# Email Configuration
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USER=your_email@gmail.com
EMAIL_PASS=your_email_password
EMAIL_FROM=your_email@gmail.com

# Application URL
NEXT_PUBLIC_APP_URL=https://yourdomain.com
```

After updating the `package.json`, install the new dependencies:

## 🧪 Testing the Integration

### Test Cards for Sandbox Mode

Cashfree provides test cards for sandbox testing. Use these cards to test different payment scenarios:

#### Successful Payment:
- **Card Number:** `4111 1111 1111 1111`
- **CVV:** Any 3 digits (e.g., `123`)
- **Expiry:** Any future date (e.g., `12/25`)
- **OTP:** `123456`

#### Failed Payment:
- **Card Number:** `4111 1111 1111 1112`
- **CVV:** `123`
- **Expiry:** Any future date
- **OTP:** `123456`

#### UPI Testing:
- **UPI ID:** `success@upi`
- This will simulate a successful UPI payment

### Test the Payment Flow:

1. Start your development server:
   ```bash
   npm run dev
   ```

2. Navigate to your checkout page
3. Fill in the shipping information
4. Verify your email with OTP
5. Click "Pay" button
6. Use the test card details above
7. Complete the payment flow
8. Verify that:
   - Payment is processed successfully
   - Order is saved in the database
   - Confirmation email is sent
   - User is redirected to success page

## 🔐 Security Best Practices

1. **Never commit `.env.local` or `.env` files to Git**
   - Add `.env.local` to your `.gitignore` file
   
2. **Use different credentials for sandbox and production**
   - Always test in sandbox first
   - Switch to production credentials only after thorough testing

3. **Protect your Secret Key**
   - Never expose the secret key in frontend code
   - All API calls with secret key should be server-side only

4. **Verify all payments on the server**
   - The current implementation fetches payment status from Cashfree
   - This prevents tampering with payment verification

## 📊 Database Schema

The database schema remains unchanged. Orders are still saved in the `checkout_orders` table with the following relevant fields:

- `order_id` - Unique order identifier (generated by your app)
- `notes` - Contains Cashfree payment ID and order ID
- `payment_status` - Set to 'paid' after successful verification
- `status` - Set to 'completed' after successful order

No changes are required to your existing database.

1. **`/api/create-payment-order/route.ts`**

## 🐛 Troubleshooting

### Issue: "Cashfree SDK not loaded"
**Solution:** Check your internet connection and ensure the Cashfree CDN is accessible. The script loads from: `https://sdk.cashfree.com/js/v3/cashfree.js`

### Issue: "Failed to create payment order"
**Solution:** 
- Verify your `CASHFREE_APP_ID` and `CASHFREE_SECRET_KEY` are correct
- Check that `CASHFREE_ENVIRONMENT` is set to either 'sandbox' or 'production'
- Ensure customer email and phone are valid

### Issue: "Payment verification failed"
**Solution:**
- Check database connection
- Verify that payment was actually completed in Cashfree dashboard
- Check server logs for detailed error messages

### Issue: Payment succeeds but order not saved
**Solution:**
- Check database credentials in `.env.local`
- Verify `checkout_orders` table exists
- Check server logs for database errors
